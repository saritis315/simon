# MILESTONES – משחק סיימון (Simon)

מסמך זה מחלק את מימוש המוצר לאבני דרך הניתנות לפיתוח, בדיקה ואישור בנפרד. מקורות האמת: `PRD.md` להתנהגות ולהיקף, `ARCHITECTURE.md` לפתרון הטכני, ו-`DESIGN.md` למבנה ולעיצוב, לרבות התמונות המקושרות אליו. אין להוסיף יכולות שאינן מופיעות במקורות.

## כללי ביצוע הפיתוח – Development Execution Rules

> **הנחיות מחייבות ל-AI המפתח:** יש לממש את ה-Milestones **לפי סדר הופעתם**. בסיום כל Milestone יש **לעצור**, להציג למשתמש את התוצר העובד, סיכום קצר של מה שמומש ותוצאות בדיקות מול **כל** סעיפי ה-Definition of Done (עובר/נכשל, עם הסבר אם יש מגבלה). **אין להתחיל את ה-Milestone הבא ללא אישור מפורש של המשתמש**. במקרה של כשל יש לתקנו ולבדוק מחדש לפני בקשת האישור. אין לפרש אישור למילסטון אחד כאישור אוטומטי להמשך.

- לכל אורך הפיתוח: ממשק בעברית ו-RTL, Mobile-First לטלפון, שני מסכים בלבד (**בית**, **אודות**), ללא Backend, Database, Authentication או AI.
- יש להיצמד ל-React, TypeScript, Vite, CSS רגיל, `useReducer`, Web Audio API, `localStorage`, `canvas-confetti`, `vite-plugin-pwa`/Workbox, Vitest ו-React Testing Library, בהתאם לתפקידיהם במסמך הארכיטקטורה.
- בדיקות ידניות מתבצעות בדפדפן מובייל או באמולציית מובייל לפי ההתאמה; בדיקות התנהגות מערכת ההפעלה, אודיו ו-PWA מחייבות אימות במכשיר תומך ככל שניתן, ובדיקת HTTPS/Offline נעשית על Build פרוס. אין להציג בדיקה שלא בוצעה כאילו עברה.
- כתובת הריפו: `https://github.com/saritis315/simon`; כתובת הפריסה: `https://saritis315.github.io/simon/`.

## Milestone 1 – בסיס אפליקציה, שני מסכים מעוצבים ופריסה ראשונה ✅

**שם ומטרה:** הקמת פרויקט Frontend עובד, שני המסכים בעיצוב עקבי ופריסה ראשונה ל-GitHub Pages, כדי שניתן יהיה להציג ולבדוק את מבנה המוצר ואת צינור הפריסה לפני חיבור לוגיקת המשחק.

**מה יש לממש:**
- פרויקט React + TypeScript + Vite עם CSS רגיל, בדיקות בסיסיות ופקודות `dev`, `build`, `test` ו-TypeScript typecheck; `base: "/simon/"` ב-Vite; קוד המקור מנוהל ב-Git Repository ב-GitHub (כבר מחובר).
- App Shell עם שני מסכים פנימיים בלבד, ניווט קבוע **"בית"** / **"אודות"**, `lang="he"` ו-RTL, ללא טעינת דף מחדש בעת מעבר.
- מבנה ה-UI לפי `DESIGN.md`: לוח Simon עגול בעל ארבעה אזורים (ירוק למעלה משמאל, אדום למעלה מימין, צהוב למטה משמאל, כחול למטה מימין), כותרת **"סיימון"**, חיווי שלב וכפתור **"התחל משחק"**; במסך אודות הסבר המשחק (בנוסח שב-`DESIGN.md`), אזור היסטוריה ריק וחיווי היעדר תוצאות.
- יישום השפה החזותית: Theme כהה מה-Mockups, צבעי ה-Style Guide וצבעי Background/Surface/Border שב-`DESIGN.md`, Typography מסוג Heebo עם Fallback (ארוז באפליקציה דרך `@fontsource/heebo`, ללא Google Fonts), חיווי **"שלב 1 מתוך 10"** לפני משחק, כפתורים, כרטיסים ופס ניווט; התחשבות ב-Safe Area והודעת "סובבו את הטלפון" במצב אופקי; ללא כפתורי הגדרות או מתג סאונד.
- **פריסה ראשונה:** Workflow ב-`.github/workflows/deploy.yml` (`npm ci`, typecheck, בדיקות, Build, פריסה ל-GitHub Pages). הגדרת Pages (Source: GitHub Actions) ווידוא שה-Repository ציבורי נעשים על ידי המשתמשת, בהדרכה צעד אחר צעד של Claude.

**תוצר מצופה:** אפליקציית מובייל מקומית שניתן לפתוח ולנווט בה בין **בית** ל-**אודות**, עם מבנה ועיצוב קרובים להמחשות, וגרסה ראשונית שלה פרוסה בכתובת GitHub Pages. בשלב זה הכפתור והלוח אינם מריצים עדיין משחק.

**Definition of Done:**
- [ ] `npm run build` ו-TypeScript typecheck מסתיימים בהצלחה; בדיקת Render/Navigation בסיסית עוברת.
- [ ] שני המסכים נפתחים ומעבר ביניהם אינו מרענן את הדף; אין מסך שלישי.
- [ ] מוצגים ארבעת אזורי הלוח במיקומים הנכונים, חיווי שלב וכפתור **"התחל משחק"**; מסך אודות מציג הסבר והודעת היסטוריה ריקה.
- [ ] כל הטקסטים הגלויים בעברית, כיווניות RTL, והתצוגה נוחה וקריאה ב-Viewport של Smartphone אנכי, ללא גלילה אופקית ובלי חיתוך באזורי Safe Area.
- [ ] האתר נטען בכתובת `https://saritis315.github.io/simon/` דרך HTTPS, עם עיצוב מלא ובלי שגיאות 404 לנכסים; ה-Workflow עבר ופורס אוטומטית.
- [ ] לא נוספו יכולות שאינן ב-PRD, ואין Backend או Database.

## Milestone 2 – משחק מלא מקצה לקצה, כולל השהיה, חידוש ומשחק חדש ✅

**שם ומטרה:** מימוש סבב משחק שלם: התחלה, הצגת רצף, שחזור, התקדמות, ניצחון והפסד עם משוב חזותי וקולי, וכן השהיה וחידוש בשליטת השחקן.

**מה יש לממש:**
- Game Engine ו-`useReducer` עם מצבי `idle`, `presenting`, `awaitingInput`, `advancing`, `finishing`, `paused`, `won`, `lost` (לפי `ARCHITECTURE.md`); רצף אקראי המתחיל בצבע אחד וגדל בצבע נוסף בכל שלב, עד 10, כולל אפשרות לחזרות על צבע.
- Sequence Controller המציג את הרצף בקצב קבוע עם Glow וצליל נפרד לכל צבע באמצעות Web Audio API, ומנהל את ההמתנות שבין השלבים ולפני הודעת הסיום. קלט חסום בזמן ההצגה ובזמן ההמתנות, ופעיל רק בתור השחקן; תגובת צבע למגע כוללת Highlight וצליל.
- אימות סדר הלחיצות ללא הגבלת זמן: מעבר לשלב הבא רק לאחר שחזור מלא; טעות אחת מפסידה מיד; השלמת שלב 10 מנצחת. הצגת **"שלב X מתוך 10"**.
- מצבי סיום עם הודעת ניצחון/הפסד, צליל סיום מתאים וכפתור **"אישור"** שסוגר את ההודעה ומחזיר למסך הבית עם **"התחל משחק"**; קונפטי באמצעות `canvas-confetti` בניצחון בלבד. ציון תוצאת המשחק כמספר **השלבים שהושלמו** (0 בהפסד בשלב 1, 10 בניצחון).
- **השהיה וחידוש:** מצב `paused` ומנגנון ביטול מלא של Playback, Timers, Highlights וצלילים פעילים במעבר למסך **"אודות"** או באירועי `visibilitychange`/`pagehide`. שימור הרצף והשלב ב-Memory בלבד ואיפוס קלט חלקי. חזרה לבית במצב מושהה עם כפתורים **"המשך משחק"** (מציג מחדש את הרצף המלא של אותו שלב) ו**"משחק חדש"** (זורק את המשחק המושהה ומתחיל משלב 1, ללא רישום). ללא Resume אוטומטי. הגנה מפני Timers/Callbacks מיושנים, ריבוי Resume ולחיצות בזמן הצגת הרצף.
- ניהול Effects ו-Timers ניתנים לביטול, והפעלה של `AudioContext` מתוך Gesture של המשתמש; טיפול גלוי בכשל התחלת אודיו ללא התקדמות שקטה מדומה.

**תוצר מצופה:** משתמש יכול להתחיל ולסיים משחק אמיתי, להפסיד או לנצח, לצאת למסך "אודות" או לרקע ולחזור, להמשיך משחק מושהה או להתחיל חדש, ולפתוח משחק חדש מיד אחרי סיום. שמירת היסטוריה תתוסף ב-Milestone 3.

**Definition of Done:**
- [ ] משחק מתחיל בלחיצה על **"התחל משחק"**; אורכי הרצף בשלבים 1, 2 ו-10 הם בהתאמה 1, 2 ו-10, ורצף קודם נשמר כרישא (תחילת הרצף) של הרצף הבא.
- [ ] ארבעת הצבעים מפיקים צלילים שונים והארה נבדלת; קצב הצגת הרצף אינו משתנה בין שלבים.
- [ ] לחיצות בזמן `presenting`, `advancing` ו-`finishing` אינן משפיעות; לחיצות נכונות מקדמות את הקלט, ולחיצה שגויה אחת גורמת להפסד ללא ניסיון נוסף.
- [ ] בדיקות מכסות הפסד בשלב 1 (0 השלמות), הפסד בשלב מתקדם, ניצחון לאחר השלמת שלב 10, מניעת שלב 11 ויצירת רצף חדש במשחק הבא (אחרי **"אישור"** ו-**"התחל משחק"**).
- [ ] בתום משחק מופיעים טקסט וצליל מתאימים; קונפטי מופיע בניצחון בלבד, ואינו מופיע בהפסד.
- [ ] רענון דף מבטל משחק פעיל ומציג מצב התחלה; אין שמירת מצב משחק פעיל לאחסון מתמיד.
- [ ] קצב ההצגה והמתנות תואמים לטבלת "קצב הצגת הרצף" ב-`DESIGN.md`; לחיצה שגויה משמיעה מיד את צליל הצבע שנלחץ, ושנייה אחר כך את צליל ההפסד יחד עם הודעת ההפסד.
- [ ] מעבר ל-**"אודות"** בזמן הצגת רצף, בזמן שחזורו ובזמן ההמתנה בין שלבים משהה את המשחק ועוצר מיד הארה וצליל.
- [ ] חזרה ל-**"בית"** אינה מפעילה את הרצף מעצמה; הכפתורים **"המשך משחק"** ו-**"משחק חדש"** מופיעים במשחק מושהה בלבד.
- [ ] **"המשך משחק"** מציג מחדש את כל הרצף הקיים, גם אם חלק ממנו הוקש קודם; השלב אינו משתנה ואין תוספת צבע חדשה. **"משחק חדש"** מתחיל שלב 1 עם רצף חדש.
- [ ] הסתרת האפליקציה וחזרה אליה פועלות לפי אותו כלל השהיה/חידוש, ללא שינוי לא צפוי כתוצאה מ-Callback שבוטל.
- [ ] מעבר לאודות או הסתרה בזמן ההמתנה שלפני הודעת הסיום אינם מבטלים את התוצאה, וההודעה מוצגת בחזרה לבית בלי צליל וקונפטי.
- [ ] משחק שהושהה אינו נחשב הפסד, ורענון דף עדיין מאפס את המשחק הפעיל.

## Milestone 3 – היסטוריית משחקים ומחיקה מאושרת

**שם ומטרה:** להשלים יכולת משתמש של צפייה בעשרת המשחקים האחרונים וניהול ההיסטוריה המקומית ממסך אודות.

**מה יש לממש:**
- History Repository ב-`localStorage`, עם רשומות של תאריך ושעת סיום, מספר השלבים שהושלמו ותוצאה (`won`/`lost`); שמירת משחק בסיומו **פעם אחת בלבד** (ברגע ההכרעה), ולא בעת השהיה, "משחק חדש" או Refresh.
- שמירת עד עשרה משחקים בסדר החדש לישן, כולל הסרת הרשומה הישנה ביותר בהכנסת רשומה נוספת.
- מסך **"אודות"** מציג רשימת כרטיסי היסטוריה, חיווי ריק כשאין רשומות וכפתור **"מחק היסטוריה"** (מוצג רק כשיש רשומות).
- Dialog לאישור מחיקה עם **"ביטול"** ו-**"מחק"**, כולל עדכון התצוגה לאחר מחיקה.
- טיפול בקריאה/כתיבה/מחיקה לא זמינים ב-`localStorage` והצגת הודעת שגיאה בעברית, בלי לחסום משחק; בדיקות להגנה מפני רישום כפול ב-React Strict Mode.

**תוצר מצופה:** לאחר סיום משחק מוצגת תוצאתו במסך אודות, נשמרת בטעינה חוזרת וניתנת למחיקה רק לאחר אישור.

**Definition of Done:**
- [ ] ניצחון או הפסד מוסיפים בדיוק רשומה אחת עם זמן סיום, מספר שלבים שהושלמו ותוצאת **"ניצחון"**/**"הפסד"** בתצוגה.
- [ ] מעבר מסכים, השהיה, "משחק חדש" ממצב מושהה, Refresh של משחק פעיל או יציאה באמצעו אינם מוסיפים רשומה.
- [ ] אחרי 11 משחקים קיימות לכל היותר 10 רשומות, בסדר מהחדש לישן; הן נשמרות לאחר Refresh באותו אחסון מקומי.
- [ ] **"ביטול"** לא משנה נתונים; **"מחק"** לאחר אישור מרוקן היסטוריה ומחזיר חיווי ריק.
- [ ] כשל אחסון אינו מונע משחק, ומוצגת הודעה מובנת בעברית כאשר פעולת שמירה או מחיקה נכשלת.
- [ ] בדיקות אוטומטיות מאמתות היסטוריה, מגבלת עשר, מחיקה, כשל אחסון ומניעת שמירה כפולה.

## Milestone 4 – PWA, Offline, עדכוני גרסה והשלמת הפרסום

**שם ומטרה:** להפוך את המשחק השלם לאתר מובייל שניתן להתקנה במכשירים תומכים ושממשיך לעבוד Offline לאחר טעינה מוצלחת, ולהשלים את הפרסום.

**מה יש לממש:**
- יצירת אייקון האפליקציה לפי הגדרת ה-App Icon ב-`DESIGN.md` (קובץ SVG מקור + PNG בגדלים 192 ו-512, כולל Maskable ו-Favicon).
- הגדרת `vite-plugin-pwa` עם Manifest (כולל `id: "/simon/app"`, `orientation: "portrait"`, `name`/`short_name` הם `Simon`), אייקוני התקנה ומשאבי Precache באמצעות Workbox `generateSW`, כולל הנכסים הנחוצים למסכים ולצלילים.
- **עדכוני גרסה:** `registerType: "prompt"`; הודעת "יש גרסה חדשה של המשחק" עם כפתור **"עדכן"** מוצגת במסך הבית רק במצב "לפני תחילת משחק", ולעולם לא בזמן משחק פעיל או מושהה (ADR-6).
- וידוא נתיב הבסיס של GitHub Pages (`/simon/`) לכל הנכסים, ל-Scope ול-`start_url`; התאמת ה-Workflow הקיים מאבן דרך 1 לפי הצורך.
- בדיקת המוצר המלא בנייד: מסכים, מגע, צלילים, השהיה/חידוש/משחק חדש, היסטוריה, ניצחון/הפסד, עדכון גרסה ו-Offline. התאמת הפריסה והנגישות הבסיסית להנחיות העיצוב, ללא הרחבת תכולת המוצר.

**תוצר מצופה:** כתובת GitHub Pages פעילה עם גרסה מלאה של המשחק; משתמש יכול לפתוח את האתר במובייל, להתקינו במכשיר תומך ולשחק ללא חיבור אחרי שהמשאבים נשמרו.

**Definition of Done:**
- [ ] Workflow ב-GitHub Actions עובר בדיקות ו-Build ומפרסם את האתר אוטומטית לאחר Push לענף `main`, ללא פריסה ידנית חוזרת.
- [ ] האתר נטען בכתובת GitHub Pages דרך HTTPS, ומשאבים/ניווט פועלים תחת נתיב הפרויקט ללא שגיאות 404.
- [ ] Manifest ו-Service Worker תקינים; אפשרות התקנה קיימת בדפדפן/מכשיר שתומך בכך.
- [ ] לאחר טעינה ראשונית מלאה ו-Precache מוצלח, ניתוק האינטרנט אינו מונע פתיחה מחדש, משחק, השמעת צלילים, ניווט או צפייה בהיסטוריה השמורה.
- [ ] כשמתפרסמת גרסה חדשה, ההודעה עם **"עדכן"** מופיעה במסך הבית ללא משחק פעיל, אינה מופיעה בזמן משחק פעיל או מושהה, ועדכון גרסה אינו מרענן או מפסיק משחק בכפייה.
